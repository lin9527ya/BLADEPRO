# 02 测绘引擎 — FOFA / Quake / Hunter 三源互补

> **何时打开：** 有公司名或域名要做资产测绘；FOFA 结果要补缺口（cert 反查/非 HTTP 端口/ICP 归属）；判断测绘结果可信度。
> **何时不打开：** 开场第一动作（先被动收集 03/04）；FOFA 对当前种子已够（**不加源省会话**）。
> 来源：src-dig 知识库/测绘补充-quake-hunter · quake/SKILL.md · infogather Mode8/15 · recon-methodology 文首（2026-09-07 蒸馏）。
> **铁律：** FOFA 是主搜；Quake/Hunter 只补**当前种子**缺口。禁开场必跑、禁双测绘工厂、429 只挖池（`dig-scope` §2.1）。**禁止把 email/key 写进对话。**

> **本部署说明（BLADEPRO）：** FOFA 已通过平台工具 `intel_search` 接入（expr 用 FOFA 原生语法，只查不入库、计入每日配额）；Quake/Hunter 仍未接通，相关步骤跳过并记入清单「未覆盖维度」。

## §1 FOFA（主搜 · MCP）

**调用：** 平台工具 `intel_search`（expr 用 FOFA 原生语法，如 `domain="x.com"`、`cert="x.com"`、`icp="12025439"`、`icon_hash="-247838494"`；不要自己 curl）。**只查不入库**：命中后要 `insert_assets` 才进资产表；每次调用计平台每日配额（默认 200）。key 在「系统设置」配置；返回 -102/-700 表示 key 失效，记入清单「未覆盖维度」，不要伪造结果。

**本机 MCP 两种表达法：**

| 方式 | 适用 | 例子 |
|------|------|------|
| **结构化参数**（常用） | 单条件/多条件 AND | `get_alerts(domain="target.com")`、`get_alerts(icp="京ICP备xxx号", status_code="")` |
| **`q` 原始语法透传** | cert/title/asn/`||` 组合/否定等高级语法 | `get_alerts(q='cert.subject.org="公司全称"')`、`get_alerts(q='domain="a.com" \|\| domain="b.com"')` |

`q` 非空时忽略结构化参数——cert/title/asn/org/region/`&&`/`||`/`!=` 全走 `q`。

**FOFA 语法备忘（`q` 里用；结构化参数等价单条件）：**

```
domain="target.com"          host="sub.target.com"       title="登录"
cert.subject.cn="域名"       cert.subject.org="公司全称"   cert="特定关键词"
icon_hash="-247838494"       asn="37963"                 org="组织名"
region="Beijing"             body="actuator"             header="application/json"
port="8080"                  server="nginx"              status_code="200"
ip="1.2.3.0/24"（C段）        asn="137718"（组织全段）      ← 段落地闭环见 03 §10
组合 && ；或 || ；排除 !=
```

**cert 点号语法（血泪教训，不可违背）：**

| 字段 | 用途 |
|------|------|
| ❌ `cert.subject_cn=` | 下划线，FOFA 不认 |
| ✅ `cert.subject.cn="域名"` | 按域名/主机名反查（最准） |
| ✅ `cert.subject.org="公司全称"` | 按主体反查全部证书资产 |
| `cert` / `cert.domain` | 模糊/根域聚合，关键字必须特定 |

**为什么 cert 反查有效：** 证书必须真实签发 → cert 字段是目标「主动声明」的资产，命中率高且含边缘资产。关键字必须足够特定：`cert="品牌泛词"` 误报 90%+；外企用英文品牌名、国内用拼音缩写。结果逐条归属人工筛（过股权闸）。**注意：cert 类查询全部走 `q` 透传**（MCP 无 cert 结构化参数）。

**实战坑：cert 直搜必须带域名过滤。** `cert="品牌词"` 默认返回大量**无域名的 CDN 边缘 IP**（实测 `cert="bytedance"` 6311 条几乎全为边缘 IP，逐条没价值）；追加 `&& is_domain=true` 后过滤出 129 条带域名记录（新族：cjjd15/16 合作方 CDN 集群、iot-http.feishu.cn 等）。**cert 查询一律带 `is_domain=true`**。

**FOFA 配额纪律（实战教训）：**

1. 省着用（日配额有限）；先 domain 搜 → 再 title 过滤（`q='domain="x.com" && title!="-" && title!="404"'` 砍无用记录）→ 再 cert 反查
2. domain 查询**翻页拉全**（121 条量级要 --page 2 才拿全）
3. 不用 body 搜（误报 + 耗配额）
4. **≥15s 查询间隔**（脚本连续调用时；3.5s 触发 429 风控）

**KFC 实战最佳三查（可复用模板）：**

```
get_alerts(domain="kfc.com.cn")                                    → 子域全量（基础）
get_alerts(q='domain="yumchina.com" && title!="-"')                 → 内部系统（过滤无用标题）
get_alerts(q='cert="百胜咨询（上海）有限公司"')                      → 证书关联 2700+ 条
```

## §2 Quake（360 · 补缺）

**前置：** 浏览器已登录 quake.360.net（playwright MCP）。**绝不用硬编码 Authorization、绝不发无 Cookie 裸请求。**

**精度分级（已实测，不可违背）：**

| 级 | 搜索方式 | data[] 返回 | 可信度 |
|----|---------|:-----------:|--------|
| A | `domain:"xxx.com"` | ✅ | 🟢 可信（~0% 误报） |
| B | `"精确短名"`（系统/品牌名） | ⚠️ 部分 | 🟡 部分可信 |
| C | `"公司全名"`（聚合） | ❌ 空 | 🟡 聚合有值但拿不到 IP |
| D | `body:"关键词"` / 无引号 | ✅ | 🔴 **70-99% 误报，禁直入资产** |

**中小企业例外：** 品牌名独特的小公司 domain 搜 0 条（Quake 未收录 DNS）时 body 反而命中真实服务。判据：命中 IP ≤10 且标题全部指向目标 → 可信；>50 且标题混杂 → 误报。`quake_host` 索引对中文无效，不浪费时间。

**100 条硬上限拼凑：** 单次 ≤100 条（`size>100` / `start+size>100` 返回空）：

- **策略 A（推荐）子域名细分**：先 `domain:"主域"` 拉 100 → 提取 hostname 列表 → 逐个 `domain:"sub.xxx.com"` 拉满 → 合并去重
- **策略 C IP 段细分**：cert 反查拿 IP 列表 → 按 /24 分组 → 逐段 `ip:"x.x.x.0/24"`（段大再切）

**两种操作方式：**

| 方式 | 做法 | 优缺 |
|------|------|------|
| 导航读文本（⭐ 数据最全） | `quake.360.net/quake/#/searchResult?searchVal=<URL编码>&selectIndex=quake_service&latest=true&size=30` 导航后读页面正文 | **能看到非 HTTP 端口**（Redis/MongoDB/SSH）；API 只返回 HTTP/HTTPS |
| 页内 JS fetch（结构化） | 页面内 evaluate 执行 `fetch('https://quake.360.net/api/v3/search/quake_service', {method:'POST', credentials:'include', body: JSON.stringify({query, latest:"true", start:0, size:100})})` | `credentials:'include'` **必须**（继承 Cookie）；hostname 常为空。⚠️ fetch 端点以官网实测为准（2026-09 快照 v3，旧 v1 端点已过时） |

**Quake 特色口：** `cert:"域名"`（发现 SSO/域控/VPN/日志内部系统）、`cert:"公司全名"`（组织反查，实测 2700+ 条量级）。

## §3 Hunter（奇安信鹰图 · 交叉验证）

**前置：** 浏览器已登录 hunter.qianxin.com。

- 语法：`domain.suffix="xxx.com"` / `cert.subject.org="公司全名"` / `title="xxx"` / `ip="1.2.3.4"`
- 导航 URL 的 search 参数是 **base64**（不是明文）：`hunter.qianxin.com/home/list?search=<base64(语法)>`；直接在页面搜索框输入更省事
- 404 就回首页再搜；结果读 snapshot/正文
- 积分 500/天用于导出，查询不限次
- **特色：ICP 主体信息直接展示** → 归属确认用（域名备案主体是不是 100% 全资链上的公司）

## §4 三源互补决策表

| 场景 | 先打 |
|------|------|
| FOFA 对当前种子已够 | **不加源**（省会话） |
| 需要 cert 组织反查全量 | Quake `cert:"公司全名"` 或 FOFA `cert.subject.org` |
| 需要 ICP 归属确认 | Hunter |
| 需要非 HTTP 端口 / 子域翻全 | Quake 导航页 |
| crt.sh 被墙要子域+IP | HackerTarget API（免费，见 03） |

**实战结论：** 三源各换着都有独家发现（KFC 实测：Quake 811 条 / FOFA 559+481 条 / Hunter 276 条互有独占），但**只在当前种子确有缺口时加源**——FOFA 条数到手不是加源理由（`dig-scope` §2.1 闸 B）。

## §5 补缺源简查（0.zone / Shodan / Censys / ZoomEye / BinaryEdge / 微步）

- **0.zone（零力）**：国内可用、免费额度，政企/关基资产覆盖好——FOFA+Quake+Hunter 都出 0 时的第四源；语法近 FOFA（`domain:"x.com"` / `cert:"公司名"`）
- **Shodan**：`hostname:target.com` / `ssl.cert.subject.CN:"target.com"` / `http.favicon.hash:-247838494`（CDN 溯源反查用，见 03 §8）
- **Censys**：`search.censys.io`，`services.tls.certificates.leaf_data.subject.common_name:"example.com"`（证书精确反查）
- **ZoomEye**（知道创宇，国内可用）：`site:"target.com"` / `app:"组件名"` / `service:"ssh"`
- **BinaryEdge**：全球暴露面+历史数据（scan.io 系），跨境目标补缺
- **微步在线 X 情报**（x.threatbook.com）：域名被动解析历史 + 关联资产图（国内可达，免费档够收集用）——CDN 溯源历史解析候选（联动 03 §8 P0）
- 适用：跨境目标、需要全球暴露面时。国内常规线不优先（速度/覆盖不如 FOFA+Quake+Hunter+0.zone 组合）。
