2. 读正文(browser_evaluate 取 document.body.innerText), 逐条提取:

## §2 APK 资产入口（收集级）

**A. App 商店枚举（App Store · iTunes Search API，免 key 直连）** —— 先枚举「全 App 台账」再取包：

```bash
python tools/itunes_enum.py --term 字节跳动                 # 品牌词 → sellerName(主体全称)+artistId 分组
python tools/itunes_enum.py --artist-id 1170416082 --out apps.csv   # artistId → 全 App(bundleId/版本日期)
```

- 原始接口：`itunes.apple.com/search?term=<词>&entity=software&limit=50&country=cn` → `lookup?id=<artistId>&entity=software&limit=200`（`--country` 换区）
- 三个反哺：①补 enscan app 维度（其只有名+市场链接，缺 bundleId/sellerName 归属判据）②新主体入 01 公司树（实测牵出「成都所见所得」=抖音来客/销帮主体）③**bundleId 代号 → 域名字典**（实测 `hubble`→AI抖音、`yumme`→抖音精选、`spark`→随变、`sicily`→可颂——拿代号猜域+测绘 title 搜）
- 局限：仅上架 App（企业分发/未上架不在）；term 搜索有模糊噪音，`--seller-contains` 过滤

**B. 包获取渠道：** **`mcp__ENScan__get_page_info(filed="app")`（批量首选，01 §0——公司全量 App 名+市场链接一次出）**；应用市场搜公司名/品牌名；官网下载页；APKPure 等第三方镜像；**GitHub/Gitee 搜 APK 泄露**——仓库/附件里常有未上架的内部测试包（搜 `<公司名> apk`、`extension:apk <品牌>`、组织 releases 附件；内部分发平台蒲公英 pgyer / fir.im 的分享链接同样暴露未公开应用）。

**直链获取（市场搜索页拿不到直链时的三条路）：**

```bash
# 应用宝: 移动 UA 才返回直链(桌面 UA 不给)
curl -s -A "Mozilla/5.0 (Linux; Android 12)" "https://a.app.qq.com/o/simple.jsp?pkgname=<包名>" | grep -oE 'https?://[^"]+\.apk[^"]*'
#   → imtt.dd.qq.com/*.apk?fsname=<包名>_<版本>.apk
# 豌豆荚: 搜索页找 app id → download/dot 302 → ucdl.25pp.com 直链
curl -sL -A "<移动UA>" "https://www.wandoujia.com/apps/<id>/download/dot" -o app.apk
# 第三方镜像兜底(mamecn 等): 页面藏 md5 命名直链, 需带 referer; 87g 有反爬错误页勿用
```

下载后必做：`file app.apk` 验 zip 完整性 + 遇截断用 `curl -C -` 续传（实测 200MB 级包易断）。

**收集阶段快筛（拿到 APK 先跑这三步）：**

```bash
# 1. 解包看包名与配置(strings 未装, 用 grep -aoE 提可读串替代)
unzip -p app.apk AndroidManifest.xml | grep -aoE '[a-zA-Z0-9._-]{6,}' | grep -E 'package|activity|permission' | head
# 2. 找 API 域名（assets 里的配置文件 + 非 URL 形式的 SDK key/凭证）
unzip -o app.apk -d apk_out/ && grep -rE 'https?://[a-z0-9.-]+\.[a-z]{2,}' apk_out/assets/ | grep -vE 'android|google|w3|schema' | sort -u
# 2b. AndroidManifest meta-data 里的 SDK key(非 URL 提不到的): 友盟 appkey/微信 appid/极光/bugly/高德
grep -aoE '(UMENG|JPUSH|BUGLY|com\.amap)[^"]*"[^"]*"' apk_out/AndroidManifest.xml | head
#   → wx appid 可反查主体(回灌 §1 小程序线); appkey 类是归属判据+钥匙线索
# 3. UniApp/DCloud 指纹快速路径
ls apk_out/assets/apps/__UNI__*/www/app-service.js   # 全部业务逻辑(JS 混淆)
ls apk_out/assets/zlsioh.dat                          # 加密配置(API 域名)
```

**UniApp 解混淆与 zlsioh.dat 密钥提取四步法（RC4+base64）**：`~/.claude/skills/src-dig/知识库/android-app-test.md` §2.3.1（定位 RC4 key → 解密 → base64 层 → 读 api_domain 真后端）。**深度逆向（四大组件/WebView/JS Bridge/加固脱壳/反调试/SSL pinning）同文件 + `工具/frida-scripts/`**。

**iOS 线（收集级一行）：** 企业分发页/manifest.plist 里的 `software-package` URL 与内嵌 API 域名直接抽（砸壳/Keychain 深度归 `ios-app-test.md`）。

**收集阶段核心产出：** APK 里抽出的 **API 域名/网关** → 新资产（过股权闸入池）；写死的租户/盐/演示号 → 记录为钥匙线索。

## §3 客户端 ↔ Web 双向串联（zcode 思想，高价值）

APK 是比 Web JS **更完整的接口地图**（不走浏览器缓存/裁剪）。两个方向都跑：

```
APK → Web：包内域名/base_url/user_id 模板/token 携带方式 → 回灌 Web 侧资产表
Web → APK：Web JS 里的接口 → 在 APK 里搜「谁消费它」→ 找到客户端特有的签名/加密逻辑
```

## §4 对象存储桶探测（S3/OSS/COS/Blob/OBS/BOS/KS3/京东云）

**批量穷举用本技能脚本（八云多区域一次跑）：**

```bash
python tools/bucket_enum.py --brand jd --suffixes prod,dev,backup,static --cloud all
# 云: s3/oss/cos/azure/obs(华为)/bos(百度)/ks3(金山)/jdoss(京东云)
# 输出 CSV: 桶名,云,区域,状态(LISTABLE🔥/PRIVATE/NEED_APPID),样例
# 已知完整桶名(JS/泄露里挖到的)直验: --known <桶名1,桶名2>
# ⚠️ 七牛/又拍走自定义加速域名、无固定桶子域, 脚本不可枚举——只从 JS/泄露找完整绑定域名
```

**手工兜底（单个桶/脚本覆盖不到的云）：**

命名组合：`{brand}` / `{brand}-prod` / `{brand}-dev` / `{brand}-backup` / `{brand}-static` / `{brand}-file` / `{pinyin缩写}` / `{brand}<当年年份>`…

```bash
# 探测（匿名可列桶/可读 = 暴露）
curl -s -m 30 "https://{bucket}.s3.amazonaws.com/" | head -20
curl -s -m 30 "https://{bucket}.oss-cn-beijing.aliyuncs.com/" | grep -o '<Key>[^<]*' | head
curl -s -m 30 "https://{bucket}.cos.ap-guangzhou.myqcloud.com/"
curl -s -m 30 "https://{bucket}.blob.core.windows.net/"
curl -s -m 30 "https://{bucket}.obs.cn-north-4.myhuaweicloud.com/"
curl -s -m 30 "https://{bucket}.bj.bcebos.com/"
# 三态判定(与脚本一致): 200+ListBucketResult=可列🔥 / AccessDenied(403,"does not belong to you")=私有存在 /
#   NoSuchBucket=不存在 / COS 需 <name>-<appid> 完整格式(NEED_APPID)
# ⚠️ OSS/COS/OBS/BOS 等是通配符 DNS(任意桶名都解析) — DNS 有解析 ≠ 桶存在, 必须 HTTP 判
```

**发现渠道：** JS 里的完整桶 URL（`grep -rE 'https://[a-z0-9-]+\.(oss|cos|s3|blob|obs|bcebos|ksyun)' js/`）；测绘 body 搜 `aliyuncs.com` + 域名；回包中的 CDN 引用。

**⚠️ 命中 ≠ 归属（桶名抢注，实测）：** 桶名先到先得——任何人可在云厂商注册 `bytedance`/`toutiao` 等品牌名桶。字节线实测：954 个探测名命中 405 PRIVATE + 2 LISTABLE，逐一验内容后 **0 个真属字节**（例：`toutiao` 金山云 KS3 可列桶 = 黑产 SEO 跳转素材集合 jsjiami→zzz.zhyuc.cn；`bytedance-*` OSS 私有桶均无法证明归属）。**归属判据**：桶内内容/引用域/Owner-ID，三者任一指向目标才可入表。字节主业务对象存储走自建 TOS（`*.bytetos.com`/`tos-cn-*`），本脚本八云模板**不覆盖 TOS**。

**子域接管候选（dangling CNAME）：**

```bash
~/go/bin/dnsx -d <sub>.<domain> -cname -resp     # dig 的本机等价
# 指向已释放的云资源 = 接管候选：
#   .s3.amazonaws.com（桶已删）/ .cloudfront.net / .herokuapp.com
#   .github.io / .azurewebsites.net / .myqcloud.com / .oss-xx.aliyuncs.com
#   .shopify.com / .fastly.net / .pantheon.io
```

**关键判定（防幻觉）：** CNAME 存在 ≠ 可接管；必须**资源已释放且可注册**（404/NoSuchBucket + 平台允许注册同名）。检测后验证接管可行性 → 这是漏洞，报告归 src-dig（`知识库/subdomain-takeover-test.md`）。收集阶段只记「候选+指纹证据」。
